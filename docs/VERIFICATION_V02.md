## 浏览器检查的边界

新增的 `npm run test:authoring:e2e` 实际运行了 3 项测试，但系统 Chrome 都在启动阶段退出，未执行到页面断言。这 3 项不能计为通过。初次执行还遇到测试 JSON 导入兼容问题，已改为文件读取后再运行，当前阻碍是浏览器进程启动限制。

已改用应用内浏览器实际检查：

- 新入口使用“班级待定”和温柔细腻的默认性格，未擅自填写学校/生日。
- 进入手机、群聊显示各成员名字、点击消息解锁相册。
- 查看照片解锁可选小游戏；错误密码提示可重试，正确密码显示成功反馈。
- 刷新 → 继续同一玩家 → 重新打开小游戏，解密状态恢复，无需再次输入密码。
- 独立 UI 测试副本中的色块图片可在消息中显示，点击打开大图，关闭后返回聊天。测试素材未加入正式故事或打包素材库。
- 390 × 844 视口：页面宽度 390，手机宽度约 367.4，无页面横向溢出；测试图片正常加载。
- 开发预览中实际显示调试面板、人物资源状态和关系变量，章节测试入口能执行配置事件；执行了当前测试周目的重置按钮。
- 生产代码未包含调试面板。玩家版与作者开发预览使用不同本地入口。

这不等于真机 Safari、所有触屏手势、所有音频格式或所有 App 页面都已完成回归。

## 保留与兼容

本轮没有修改既有原故事。人物配置保留原 id 与 storyId 的对应关系，新增 owner 档案；新测试内容只在 extensions.json 与 project.json 中配置。准备器写 work/campus/，不覆盖创作来源。

不改变 Work v1、IndexedDB 表、既有剧情 ID 或 revision；同 revision 恢复时合并新增变量默认值并保留玩家历史，资源元数据采用新构建配置。跨 revision 自动迁移尚未实现，也没有清理旧浏览器存档。

素材当前全部为明确的待提供占位。文件放入后可导入，未实际导入人物照片或录音。已有内嵌图片在未指定有效替换素材时会保留。
