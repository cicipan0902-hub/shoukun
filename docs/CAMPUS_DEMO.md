# 校园沉浸式手机 · 第一阶段演示

基于 cicipan0902-hub/shoukun 的源码继续开发，原有手机、App、事件引擎及许可保留。

## 目前可体验

- 进入前设置昵称、班级、性格。作品内称呼随资料变化，浏览器保存设定；继续故事沿用当前周目，以新设定开始创建新周目。
- 四位架空校园角色：朱志鑫、张峻豪、张泽禹、左航。人物设定见 `stories/foundation/characters.json`，不代表现实人物本人。
- 微信私聊、五人群聊、朋友圈、微博、相册、模拟来电与 Instagram 动态。
- 主线选项和日常 AI 私聊并存。AI 入口在四位角色的微信私聊顶部，群聊目前只走预设剧情。
- 自由聊天与主线进度分开保存，不执行模型生成的事件，不提前发送隐藏线索。模型只接收当前私聊中已经可见的剧情消息及最近 12 条日常消息；这是有限窗口记忆，不是无限长期记忆。

## 试玩顺序

1. 设置昵称、班级和性格，点击「让故事发生」，解锁手机。
2. 微信 →「放学别走（5）」→ 点击最后一条群消息。
3. 相册 →《篮球场边的背影》。
4. 微信 → 朱志鑫 → 点击消息气泡 → 选择回复。
5. 等待 6 秒的模拟来电。接听可看通话文字，再挂断；拒接也能继续。
6. Instagram →《放学以后》→ 选择章节落点。
7. 支线：微信 → 发现 → 朋友圈 → 点击学长动态，解锁备忘录中的草稿。微博也可作为照片线索的另一入口。

角色回复、关系进展与章节结束只是本阶段演示，不是最终剧情。相册用框架的标题占位图，来电为文字演示，无真人照片或合成声音。

## 启动

Node.js 22，安装依赖后执行：

```sh
npm ci
npm run foundation:build
npm run campus:serve
```

服务默认在 4173 端口，同时提供网页和 AI 接口；如果旧预览占用端口，可设置 `PORT=4174 npm run campus:serve`（macOS/Linux）。本次演示使用 4174。手机连同一 Wi-Fi 后使用电脑的局域网 IP 和对应端口。

单独的 `foundation:dev`、`preview:lan` 只提供前端与主线预览，不包含 AI 后端。

## 连接日常 AI

本次没有配置密钥，也没有请求真实模型。未连接时界面显示「AI 还没连接」，主线照常可玩。

1. 将 `.env.example` 复制为项目根目录 `.env`。
2. 在本地 `.env` 填入自己的 `AI_API_KEY`、`AI_MODEL`；`AI_BASE_URL` 默认为 OpenAI，其他服务需支持 HTTPS Responses API。密钥不要发到聊天、不要提交仓库、不要使用 `VITE_` 前缀。
3. 重启 `campus:serve`。进入角色私聊，切到「日常私聊 · AI」。发送时才向该模型服务传递本次所需的昵称、班级、性格与最近上下文。

接口使用服务端鉴权、30 秒请求超时和有限频率控制；错误时保留输入文字。接口请求按官方规范使用 `instructions`、`input` 和 `store: false`，参考 [OpenAI 文本生成文档](https://developers.openai.com/api/docs/guides/text)。服务商的实际数据处理规则仍以所选服务为准。

当前后端适合本地或可信局域网试玩，没有玩家登录和独立计费账户。要公开提供付费模型接口，需先增加玩家认证与额度管理。GitHub Pages 只能托管静态主线，不能执行此 Node 后端；完整 AI 版本需托管到可运行服务端的平台。

## 验证与边界

- 主线校验与 8 条路径回放覆盖两种私聊回复、接听/拒接和两个章节落点，包含可选朋友圈线索与微博入口。
- 新增个性化测试覆盖输入校验、资料损坏恢复、周目隔离、HTTP 局域网可用的 ID 生成及个性化剧情。
- 后端测试使用明确标记的模拟响应，覆盖请求格式、角色限制、服务端密钥、上下文和上游失败；不代表真实模型的人设效果已验证。
- 本次未推送或公开发布。完整真机、离线与自动浏览器回归仍需后续检查。
