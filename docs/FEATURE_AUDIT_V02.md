## 数据边界与兼容

`stories/foundation/story.json` 保持本轮之前的原内容。新增内容写入 extensions.json，准备过程只写 work/campus/，然后交给原编译器生成 public/work.json。

原 Work formatVersion、事件动作类型、人物联系人 ID、故事 ID、revision 与 IndexedDB 表结构保持原样。同一 revision 的旧存档会补充新变量默认值，保留玩家已有变量、选择和解锁；author.* 资源清单使用新构建数据。跨 revision 仍按上游规则开始新进度，不承诺自动迁移。

作者备注不进入运行包。人物公开简介、剧情文本和谜题数据仍属于静态游戏资源，不能当作保密系统。年龄、正式年级、学校、生日与时间线均待定；原演示中的日期和年级字样仅作为已存在测试内容保留。

## 后续 App 优先级

| 优先级 | 功能 | 现有入口 | 接入方式与边界 |
| --- | --- | --- | --- |
| P1 | 校园论坛 / 匿名投稿 | forum | 用 content.forum 和 meta/帖子详情，read 触发线索；匿名是故事内设定 |
| P1 | 日历 / 校园活动 / 待办 | calendar、reminders | 配置日期、事件与完成后的变量，配合现有跨 App 事件 |
| P1 | 日记 / 未发送信件 / 心情 | notes | folder 分类、password、hidden、unlock，适合独立人物线 |
| P2 | 音乐 / 录音 | music、files，及音频 Item | 导入授权 MP3/WAV/OGG，利用原音频播放器；独立录音 App 需注册新 App |
| P2 | 邮件 / 活动信息 / 成绩通知 | mail、calendar、notes | 现有记录页面；复杂成绩系统先用内容与状态，避免虚假“真实学校服务” |
| P2 | 回忆收藏 | 相册收藏 / 原内容收藏机制 | 可先引用已有内容；独立回忆时间轴需新 UI |
| P3 | 考试问答 / 时间线排序 / 拼接信件 / 节奏游戏 | 新增受控小游戏编译器或独立组件 | 先扩展类型白名单和结果事件，再加入配置；不能在 JSON 中执行 JS/HTML |
