# 女主备忘录与内心独白：长期创作规范

此规范适用于所有正式章节。女主的记录是一条持续变化的叙事线；章节聊天提供事件，备忘录呈现她没有直接说出口的另一层感受。

## 每章交付

每个正式章节至少有一篇完整的个人记录，通常150–300字；重要转折可以有2–3篇较短记录。字数是参考，重点是具体、不重复。章节入口、攻略、任务清单、结尾的一句短签不能替代完整记录。

每篇选一个实际事件和两三处具体细节，例如饮料冰手、交回纸单、铅笔印、没理完的数学错题。允许写一半转话题、想得太多又自嘲、问题没有答案；不需要每次都做成熟总结。

她温柔细腻、有共情力，也会内耗、怕让亲近的人失望。哥哥是能够争执又互相理解的人，不是只负责撮合的工具。写暗恋时，可以承认外貌吸引、分心和过度想象；对真实人物的理解必须来自已经发生的互动，不能提前获得未来章节的认知。

学习、朋友、音乐、家庭、方向和日常都可以成为主题。不要把所有记录都写成恋爱心情，也不要每篇都重复完整人设。避免演讲、名言堆砌和“我终于懂得真正的爱情”一类越过经历的结论。

## 作者规划

在 stories/foundation/memo-plan.json 为每篇主记录登记：关联章节、记录ID、关联事件、主题、当时的认知或情绪、后续呼应、能否提前看。此文件不被编译器加载，不进入玩家网页；仅供作者管理。

当前脉络：

| 第一章 | 开学第一天 | 明明不认识他，为什么已经替他补了那么多细节？新课表、错题和谢谢哥哥也还没处理。 |

## 配置与解锁

记录继续使用原备忘录App，在章节 content.notes 配置稳定ID、标题、正文。事件解锁的记录设 hidden=true，只在关联事件实际发生之后由 unlock 动作开放。章节入口可使用 hidden=false 加 unlock 条件键，以兼容新增章节前已经完成上一章的旧存档。

规划表中的作者备注不能放进 note.body、meta 或公开角色简介。正文可用第一人称，不展示“待作者填写”“认知阶段”等编写术语。

阅读仍走原 read 事件，读过的状态随原存档保存。阅读记录只能触发已具备条件的事件；必须用阶段、任务完成与必要阅读条件限制结局，不允许打开备忘录就自动跳过尚未发生的工作。

第三章的记录在现场两种回应后解锁。玩家可先读，但必须同时看过更新节目单及哥哥的工作动态，第三章才结束。旧记录不改ID，不重置阅读状态。

## 交付自检

- 能指出记录对应的本章事件，也能找到未在聊天中直接说出的个人感受。
- 至少有一两处能落到手、物品、地方或动作上的具体细节。
- 语气符合开篇阶段的高中生，允许困惑，不硬写正确答案。
- 不泄漏人物秘密，不复述角色简介，不提前解释未来重大情节。
- 未解锁不可见，回看不重复发消息，章末有可读主记录。

第四章沿用同一规范：按Demo回应只解锁《没接上的那一段》《还想等后面》或《先把手头的做完》之一。记录具体表达、尝试或工作边界，穿插订正和兄妹晚饭，不猜测朱志鑫的私人想法。三篇的规划均在memo-plan.json，后续可据真实音频调整听感措辞。
